# 완료 보고 전 검증 에이전트 단계
날짜: 2026-09-02
결정:
- 마일스톤·기능 작업의 완료 보고 전에 **작업한 에이전트가 아닌 별도 검증 에이전트**를 실행한다. 절차와 판정 기준은 `docs/verification_checklist.md`, 루틴은 CLAUDE.md 9절.
- 검증 에이전트는 (1) import → 데이터 빌드 → 아트 검증 → gdUnit4 전체, (2) `test/tools/playthrough_check.gd`(창 모드 자동 플레이: 시드 고정 이틀, 상태 검사 18항목, 단계별 PNG 8장, `playthrough_report.json`) 을 직접 돌리고, (3) PNG 를 **직접 읽어** 체크리스트 표와 대조한 뒤 항목별 PASS/FAIL/판단불가 를 보고한다. FAIL 이 하나라도 있으면 완료가 아니다.
- 플레이스루 스크립트는 시드에서 방문자가 안 나오면 손님을 직접 세워 심사·손님 카드·손님 액터 경로를 반드시 지나가고, 밤에는 튜토리얼을 넘긴 뒤 `kind=story` 이벤트가 떠 있는지를 검사한다(대화창이 떠 있기만 하면 통과하던 느슨한 검사를 강화).
- 손님(뜨내기)은 배치 대상이 아니지만 배치 패널에 **정보 카드**("손님 · 이름 / n일 뒤 떠남 · 배치 불가")로 보인다. 카드 수 = 하숙생 + 손님.
- 튜토리얼 대화가 끝나면 같은 페이즈의 사연(story)이 이어서 뜬다. 사연끼리는 하루 하나.

이유:
- 같은 종류의 실수가 세 번 반복됐다: 픽셀 폰트 크기(축소 화면만 보고 판단), 드래그 드롭(0×0 Control, headless 로는 안 잡힘), 카메라 오프셋(대화창 뒤에 가려진 빈 화면). 셋 다 단위·통합 테스트는 전부 통과한 상태였다. 헤드리스 테스트는 GUI 입력과 실제 렌더를 검증하지 못하므로, 실제 창에서 플레이어가 보는 화면을 사람 대신 읽는 단계가 필요하다.
- 첫 실행에서 검증 에이전트가 "1일차 밤에 사연이 안 뜬다" 를 잡아냈다(자동 검사는 튜토리얼 대화창으로 통과). 단계의 가치가 확인됨.

대안과 기각 사유:
- 작업 에이전트가 스스로 캡처를 보고 판정: 이번 세션에서 반복 실패한 방식. 자기 결과를 확인 편향 없이 보기 어렵다.
- headless 통합 테스트 강화만으로 대체: InputEvent·렌더가 없어 근본적으로 못 잡는 영역이 있다. 보완이지 대체가 아니다.
