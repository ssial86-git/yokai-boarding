## 0. 전제 (확정 사항 요약)

Godot 4.7 + GDScript, PC(Steam) 우선, 경영·성장 중심, 단면 뷰 + 방 단위 증축(자유 건설·플랫포밍 없음), 요괴 파견 + 자동전투, 아트는 픽셀(인게임) + 일러스트(대화·도감) 혼합, 1인 + Claude Code, 서사는 **안 B 「대차대조표의 왕」 확정판**(05 문서 7절 — 하숙부 기록이 말소로부터 요괴를 지킨다). FST 병행 시 아래 기간은 그만큼 늘어난다.

## 1. 슬라이스가 증명해야 하는 것

1. **핵심 루프 가설**: "배치 → 가동 → 정산·심사 → 증축"의 하루 사이클이 15분 안에 재미있는가. 특히 **아침 배치가 매일 고민되는 퍼즐인가** (고민이 없으면 방치형과 다를 게 없다).
2. **파이프라인 가설**: 요괴 1명(csv 행 + 스프라이트 + 사연 이벤트)을 코드 수정 없이 추가할 수 있는가.
3. **톤 가설**: 임시 아트로도 "포근한 요괴 하숙집"이 전달되는가. 어둑이의 '관심받으면 또렷해짐'이 말없이 이해되는가.

## 5. 기술 결정 (v1에서 바뀐 것만)

- **월드 → 하숙집 구조**: TileMapLayer 자유 지형 대신 **방 슬롯 그리드**(3×4 배열 + 방별 내부 씬). 직렬화는 방 배열 + 요괴 상태 + 이벤트 로그. v1의 청크·지형 생성기는 폐기.
- **요괴 AI**: 페이즈 기반 상태머신(이동→일→휴식). 경로는 방 그래프 탐색이면 충분 — 내비메시 불필요.
- **자동전투(Tier 2)**: 로직은 순수 GDScript 클래스로 만들어 **Python 시뮬레이터와 동일 수식 공유**(밸런스는 시트에서). 연출은 결과 재생만.
- **대화·사연 이벤트**: `dialogue.csv` + 조건식(호감도·소지품·날짜). 분기 5개 이하의 단순 구조로 시작.
- 데이터 주도·씬 얇게·Events 버스·gdUnit4 원칙은 v1 그대로 (03 CLAUDE.md).

## 6. Go / No-Go 기준

1. 테스터 5명 중 3명 이상이 15분 후 유도 없이 "내일 누굴 어디에 둘지" 계획을 말한다 (배치 퍼즐 성립).
2. 테스터가 증축 없이는 5일차 이후 진행이 막힌다 (증축이 필수 동기).
3. Claude Code 세션 1회 30분 내에 Y04(바리)를 데이터+임시 스프라이트만으로 추가하고 테스트 통과 (파이프라인).
4. 세이브 왕복 후 방·요괴·호감도·이벤트 로그 동일 (자동 테스트).
5. 테스터가 게임의 분위기를 한 문장으로 말하고, 그 문장에 '포근/귀엽' 계열 단어가 들어간다 (톤).
6. 어둑이의 변화를 테스터가 텍스트 설명 없이 알아챈다 (핵심 규칙의 시각 전달).
